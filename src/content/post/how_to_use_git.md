这篇文章原来是一份标准的 Git 入门教程：什么是 Git、核心概念、命令速查表、工作流程图……回头再看，网上同款教程一搜一大把，AI 更是张口就来，我这份既不比别人全，也没有任何我自己的东西。留着它纯属占地方。

所以我把整篇删了，换成我现在真实的用法：遇到任何 Git 问题，直接问 AI。

但「直接问」也有技巧。Git 的回答质量高度依赖上下文——你在什么分支、改没改过历史、有没有推到远程，答案可能完全相反。所以关键是把自己的情况一次性说清楚。下面这段提示词是我自己在用的，复制过去，把尖括号里的内容改成你的情况就行：

```text
我是 Git 新手，请当我的 Git 教练。

我的情况：
- 场景：<个人项目 / 小团队协作>
- 远程仓库：GitHub
- 当前状态：<把 git status 的输出原样贴在这里>
- 我想做的事或遇到的问题：<一句话描述，比如「我提交错了想撤销」「我想把这几天的修改同步到 GitHub」>

要求：
1. 直接给出可以复制执行的命令，每条命令后一句话解释它做了什么
2. 如果操作有风险（可能丢代码、改写历史），先警告我，并先给出备份方法
3. 每步执行完，告诉我怎么验证成功了（git status 或 git log 应该看到什么）
4. 只解决当前这个问题，不要展开教学；涉及的概念顺带一句话解释即可
```

用下来最有效的是第 3 行：把 `git status` 的输出原样贴过去。它包含了分支名、暂存状态、与远程的差距，AI 拿到这个基本不会答偏。

最后留几条我觉得不用问 AI、值得直接记住的：

1. 看不懂 `git status` 在说什么，就把它整段发给 AI，这是最快的学习方式。
2. 提交之前 `git diff` 扫一眼，你会拦下很多不想提交的东西。
3. 凡是带 `--force` 或 `reset --hard` 的命令，让 AI 先解释清楚会发生什么再跑，这两个是仅有的能真正弄丢东西的操作。

教程会过时，提示词不会——因为答案每次都是根据你当下的情况现生成的。
